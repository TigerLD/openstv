# Формат Fluke `.tst` — что удалось выяснить

Образец: `samples/5.tst`, 26 209 байт. Создан прибором Fluke Networks
(LinkWare), судя по содержимому — тест медного кабеля, не OTDR.

## Контейнер

Файл состоит из записей. Каждая запись:

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 2 | маркер `FE BA` |
| 2 | 2 | тип записи (big-endian) |
| 4 | 2 | параметр (в образце 1, 4 или 8) |
| 6 | 2 | параметр (номер/версия) |
| 8 | 4 | длина данных (big-endian) |
| 12 | len | данные |
| 12+len | 4 | контрольная сумма / хвост (у сжатых записей — конец zlib-потока) |

Фактический шаг до следующей записи: `12 + len + 4`.

## Записи образца

| Тип | Длина | Содержимое |
|---|---|---|
| 1 | 4 | служебное значение |
| 10 | 72 | паспорт: `P-4.40`, `PIROGOVO`, дата/время |
| 11 | 1176 | zlib-поток: 2252 байта, таблица параметров/событий |
| 12 | 22797 | zlib-поток: 34063 байта, массив отсчётов теста |
| 14 | 416, 394 | результаты по парам |
| 15 | 19 | строка `Cat6` |
| 13 | 1203 | zlib-поток: 7308 байт, `GOST R 53245-2008 Chan Cat6`, `SPEC_MAP`, `T568B` |

У сжатых записей данные начинаются с 8 байт: два big-endian `u32`
(в образце 617/2252, 564/34063, 646/7308), затем zlib (`78 5E`).
Второе число совпадает с размером распакованных данных.

## Вывод

В образце нет OTDR-рефлектограммы: это сертификационный тест витой пары
(категория Cat6, ГОСТ Р 53245-2008). Поэтому конвертер `.tst` → SOR
невозможно проверить на этом файле. Для реализации нужен образец
`.tst`, созданный OTDR-модулем Fluke (LinkWare содержит блок OTDR
с массивом точек и событиями).

Текущее поведение OpenSTV: `.tst` не входит в список расширений для
сканирования; попытка разобрать его как SOR даёт понятную ошибку.
